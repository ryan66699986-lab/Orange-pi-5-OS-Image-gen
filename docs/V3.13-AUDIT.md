# V3.13 pre-build audit

Date: 2026-08-24

Scope: repository source, V3.11 build log, source resolution, ARM64 artifact recipes, target rootfs customization, session/storage behavior, final image inspection and hardware acceptance gates.

## Media-client decision

Stremio remains the media client.

| Criterion | Native Stremio | Lumera |
|---|---|---|
| Target platform | Native Linux GTK/Wayland | Android TV |
| ARM64 ABI | Linux/glibc AArch64 | Android/Bionic `arm64-v8a` |
| Playback engine | Embedded libmpv | AndroidX Media3 ExoPlayer |
| RK3588 integration available to this image | Direct linkage to the pinned V4L2 Request FFmpeg/mpv stack | Would require an Android container and compatible Android codec/HAL integration |
| Controller UI | Adequate through the existing Gamescope/ES-DE port launcher | Strong Android TV/D-pad design |
| 4 GB memory/platform risk | One native application stack | Additional Android userspace/container and graphics/media bridge |
| Hardware-decode proof path | Build checks, standalone probes, visible probes and Stremio-process log evidence | No native Linux V4L2 Request proof path |

Lumera is a promising Android TV UI, but it is not a drop-in native Linux ARM64 client. Its official repository uses the Android application plugin, Android TV launcher integration and Media3 ExoPlayer. The `arm64-v8a` build target does not make it executable on Ubuntu. Adopting it would turn this into an Android-container integration project and would make the mandatory RK3588 hardware-decoding result less deterministic.

## Defects corrected before V3.13

| Area | Audit finding | V3.13 correction | Failure timing |
|---|---|---|---|
| FFmpeg/OpenSSL | Ubuntu 26.04 provides OpenSSL 3; FFmpeg configured with GPL + OpenSSL but without Version 3 licensing | Added `--enable-version3` and an early recipe assertion | Previously late, during Stremio media build |
| FFmpeg source | A branch was resolved, then cloned later by branch name | Fetch and detach the exact resolved commit | Eliminates moving-branch race |
| mpv/Stremio source | Tags were checked, then cloned later by tag | Resolve, record and fetch exact commit SHAs | Eliminates moving-tag race for the media chain |
| Embedded libmpv | User `mpv.conf` was not a sufficient guarantee because embedded libmpv does not load config by default | Patch the pinned Stremio initializer to set `hwdec=v4l2request-copy` and `hwdec-codecs=all` | Build-time and runtime guarded |
| Stremio evidence | Standalone `mpv --vo=null` proved the decoder but not the Stremio process | Add debug logging and `opi-stremio-session-check` | Hardware acceptance gate |
| Decode coverage | Only H.264 and HEVC 8-bit probes existed | Add an asserted HEVC Main10 probe and visible mode | Hardware acceptance gate |
| Build order | Stremio and the previously failing Snes9x recipe ran last | Run Stremio first and Snes9x second | High-risk failures move to the beginning |
| CMake install | Six native recipes suppressed install failures and could retain only a binary | Make CMake install errors fatal; retain explicit binary checks | Artifact-local immediate failure |
| Native linkage | Only part of the custom emulator set received target-root `ldd` inspection | Inspect ES-DE, RMG, Flycast, melonDS, Azahar and Snes9x too | Before Armbian image creation completes |
| USB ROMs | `udiskie` automount ran only in Labwc | Run and supervise it in the default Gamescope/ES-DE child | Runtime behavior corrected |
| Offline QA syntax | The outer script parser treated the embedded QA body as heredoc text | Extract and parse the embedded QA program in `tools/check.sh` | Before build starts |
| CI | Static checks did not run on pushes to `main` | Add the `main` push trigger | Repository change gate |
| Metadata | A rootfs log label still named V3.10 | Use an unversioned runtime log prefix | Removes misleading diagnostics |

## Layers reviewed

- Fresh workspace deletion and version-derived paths remain intact.
- Image build targets Orange Pi 5 Pro, Ubuntu 26.04 Resolute, AArch64 and Armbian edge.
- Kernel overrides still require Rockchip VDEC, Panthor, DRM, V4L2/media-controller, controller, Wi-Fi, Bluetooth and HDMI-CEC support.
- The old RetroArch/libretro/XFCE/LightDM stack remains forbidden.
- Native emulator command coverage and final target-root presence checks remain enforced.
- Rootfs package consistency, sudoers, TOML, JSON and XML syntax, GSettings, desktop metadata, systemd enablement, zram, swap and service conflicts remain gated.
- The final raw image is mounted read-only for offline inspection and receives a SHA-256 plus build manifest.
- No NVMe formatting, partitioning, installation or boot migration command exists in the build profile. The NVMe remains outside the OS flow until the image is finalized.

## Risks that cannot be eliminated statically

- Armbian `edge`, Ubuntu Resolute packages and the underlying Linux 7.1 hardware behavior still require a real-board test.
- Panthor/PanVK display, Gamescope scanout, HDMI mode negotiation and visible decoded frames cannot be proved in QEMU.
- Wi-Fi, Bluetooth, HDMI-CEC, audio, controller compatibility, thermals and 4 GB memory pressure require the board.
- DuckStation's upstream `latest` asset and the optional Steam seed are mutable and are not reproducible source builds. V3.13 records the exact SHA-256 of every downloaded payload in the final lock manifest, so the tested bytes remain identifiable even when the upstream URL changes.
- Several non-media emulator recipes still begin from verified release tags. V3.13 records the exact resulting commit from every native build, but a future hardening pass should resolve each tag once and pass exact SHAs into every recipe before compilation.
- A successful standalone decode probe is necessary but not sufficient; visible playback and the Stremio-process check remain mandatory.

## Required hardware acceptance sequence

1. Verify the produced raw image with its SHA-256 and flash separate test media.
2. Boot with the NVMe installed but untouched; confirm the system still boots entirely from the SD test image.
3. Run `opi-validate` and save its complete output.
4. Run `opi-stremio-hwcheck`; H.264, HEVC and HEVC Main10 must pass.
5. From the graphical session, run `opi-stremio-hwcheck --visible`; all probes must display correctly and pass.
6. Play representative H.264 and HEVC content inside Stremio, then run `opi-stremio-session-check`.
7. Validate Gamescope/ES-DE, Labwc fallback, controller OSK, USB ROM automount, each emulator family, Moonlight, browser, network, Bluetooth, audio and HDMI-CEC.
8. Stress media and emulation long enough to inspect memory pressure, thermals and systemd failures.
9. Only after all gates pass should the project add an SD-boot/NVMe-root migration path. That operation must identify the target by stable device identity and require explicit confirmation.
