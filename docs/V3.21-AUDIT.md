# V3.21 V3.20-log audit and correction

## Scope

The complete V3.20 log `build(20260826-004030).log` contains 48,431 lines. The audit identified the first causal failure, separated later Armbian/Docker cleanup from that cause, reviewed warning and feature-probe signatures, and traced the missing library through the isolated gamepad build, generated runtime manifest and final target gates.

## Proven before the stop

V3.20 passed host disk, Docker/loop, ARM64 binfmt/QEMU, immutable-source, Resolute package, Stremio ABI/toolchain, distro executable, official Brave/Firefox and edge-kernel preflights. The fresh-workspace rule was enforced and Armbian edge kernel 7.1 reported Rockchip VDEC, Panthor and DRM configuration.

DuckStation and ARMSX2 AppImages extracted successfully. Snes9x, native Stremio, PPSSPP, ES-DE, gamepad-osk, Moonlight, RMG, Flycast, melonDS and Azahar all completed their ARM64 artifact stages; Azahar reported 64 of 64 tests passing. Steam ARM64 and GE-Proton staged. The artifact collision audit found 4,388 unique paths, the merged target package set solved on Resolute ARM64, hardware-decoding probes were generated, and the final pre-Armbian static audit passed.

Armbian then built the kernel/root filesystem, installed the official ARM64 browsers and the assembled overlay, configured the `ryan` user, emulator/session/media/controller/browser/audio/storage/performance policy and entered the build-time target-root sanity gate. V3.20's gamepad mouse normalizer passed—the prior V3.19 failure did not recur.

## Terminal result and cause

The target-root ELF closure check stopped on:

```text
Unresolved shared library in /usr/local/bin/gamepad-osk:
        libSDL3_ttf.so.0 => not found
```

`gamepad-osk` was compiled with `libsdl3-dev` and `libsdl3-ttf-dev`. In that isolated container, APT installed both `libsdl3-0` and `libsdl3-ttf0`, so compilation and build-container linkage succeeded. The final target happened to contain `libSDL3.so.0` through other generated dependencies, but its package manifest did not retain `libsdl3-ttf0`. This is a runtime-package closure omission, not a source, compiler, controller-configuration, Stremio, Moonlight, kernel or emulator failure.

The build stopped before completed-image offline QA, raw-image copy, SHA-256/manifest output and the success report. No usable V3.20 image was produced. Real board graphics, decoding, controller, audio and emulator operation remain unproven.

## V3.21 correction

- Add `libsdl3-0` and `libsdl3-ttf0` explicitly to the base runtime package manifest.
- Add the same direct runtime dependencies to the gamepad artifact manifest after generic dependency collection and assert both entries.
- Before Armbian, create a clean Resolute ARM64 environment, install the complete generated target package set, copy in the merged overlay, run `ldconfig`, and reject any unresolved ELF dependency across critical custom application roots.
- Require the pre-Armbian gamepad linkage report to resolve both `libSDL3.so.0` and `libSDL3_ttf.so.0`.
- Require both packages in the target-root package gate, both resolved SONAMEs in the target-root linkage gate, and both library files plus package records in completed-image offline QA.
- Add static assertions and embedded-shell syntax validation for every new guarantee.

This layered correction does not depend on the generic runtime collector behaving perfectly: the direct manifests are authoritative, the clean merged-runtime preflight exercises them, and two later gates independently check the assembled image.

## Warning and probe classification

- GCC warnings are emitted by pinned FFmpeg/emulator dependencies whose responsible builds and tests completed. They remain candidates for upstream review but are not the terminal failure.
- CMake `not found`/failed feature tests refer to optional, foreign-platform or CPU-extension probes unless followed by a failed configure/build; the responsible artifacts completed.
- Armbian's U-Boot branch-shaped tag probes recovered to the valid pinned source.
- Offline-root service-start suppression, fake `start-stop-daemon`, empty `COLUMNS`, desktop-category hints and container-hostname `sudo` warnings are packaging-environment diagnostics and did not stop installation.
- Orange Pi 5 Pro edge remains outside Armbian's kernel test target list, so a successful image still requires all physical gates.

V3.21 must start from a completely fresh workspace. Stremio hardware decoding remains a hard requirement and must be proven during real Stremio playback; standalone media probes alone are insufficient. The NVMe remains read-only during image testing.
