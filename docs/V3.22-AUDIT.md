# V3.22 whole-image audit

## Scope and conclusion

This audit re-examined the complete repository rather than only the last reported failure. It covered all supplied build logs through `build(20260826-004030).log`, the generated package flow, kernel configuration, every native and AppImage artifact path, root filesystem customization, offline image inspection, runtime helpers, controller/audio/display/network/storage policy, source immutability and documentation.

V3.21's SDL3_ttf repair remains valid. The audit nevertheless found seven material assurance gaps. V3.22 converts each into a fail-closed build or hardware gate. The repository can now be considered ready for another fresh build; it cannot be called final until the generated image and real Orange Pi 5 Pro pass the physical validation matrix.

## Findings and closures

| Severity | Finding | V3.22 closure | Earliest failure point |
|---|---|---|---|
| Critical | Panthor kernel configuration did not install or prove a PanVK Vulkan ICD | Explicit `mesa-vulkan-drivers`, Panfrost ICD assertions and `opi-gpu-check` reject software Vulkan | ARM64 package solver; then target/offline/runtime |
| High | DuckStation and ARMSX2 executable dependencies were outside merged ELF closure | Require both `AppRun` launchers; build bundled-library paths; scan every executable ELF before Armbian and in target | Pre-Armbian runtime closure |
| High | DuckStation used a mutable rolling download with no expected digest | Bind release ID `368956550` and ARM64 SHA-256; mismatch aborts before extraction | AppImage download stage |
| High | HDMI audio was described as default but never selected | Global user oneshot selects the first HDMI/DP sink once and records success; subsequent choices are untouched | Target/offline structure, then first-session runtime |
| High | CEC adapter support did not imply TV-remote input | Require `RC_CORE=y` and `MEDIA_CEC_RC=y`; runtime requires a CEC adapter, RC input and responsive topology | Kernel staging/offline config, then hardware runtime |
| High | Onboard wireless firmware was assumed | Require Armbian firmware package plus Broadcom SDIO Wi-Fi and HCD Bluetooth payloads | Target root, offline image and hardware runtime |
| Medium | Display helper selected the first/current output, not the best attached display | Rank all enabled outputs using EDID-preferred/native area then refresh; retain safe fallback and HDR EDID gate | Static payload validation, then launch/runtime |
| Medium | “Any filesystem” exceeded the prior Ext/Btrfs/FAT/exFAT/NTFS set | Add F2FS, XFS, ISO9660 and UDF kernel gates plus F2FS/XFS userspace tools | Package solver and kernel staging/offline config |

## Layered gate matrix

### Before native compilation

- Ubuntu Resolute ARM64 must solve every declared base and build package, including PanVK and filesystem tools.
- Source tags/commits and expected layouts remain validated.
- DuckStation's expected release identity and SHA-256 must be syntactically pinned.
- Kernel overrides must include Panthor, Rockchip VDEC/DRM/audio, CEC RC, input/controller, wireless and filesystem symbols.

### Before Armbian starts

- Each AppImage must be AArch64 and contain a valid embedded SquashFS plus executable `AppRun`.
- DuckStation must exactly match the reviewed digest.
- All artifacts must merge without path collisions.
- A clean ARM64 container installs the final generated runtime package set.
- Core custom ELF closure and extracted DuckStation/ARMSX2 executable closure must contain no unresolved dependency.

### Target root

- `dpkg --audit`, `apt-get check`, sudo policy, desktop files, schemas, JSON, TOML and XML must validate.
- PanVK package/ICD, Armbian firmware and Broadcom payloads must exist.
- DuckStation/ARMSX2 launchers and executable dependency closure must pass.
- HDMI-first oneshot audio helper and global enablement must exist.
- Stremio and Moonlight must still resolve the dedicated V4L2 Request media prefix.
- Every mandatory emulator, browser, controller/session helper and storage tool must exist.

### Completed raw image

- The image is mounted read-only and repeats critical file/package checks.
- The compiled kernel must retain CEC RC and the expanded filesystem symbols as well as existing graphics/video/input/audio/wireless requirements.
- Panfrost ICD, firmware payloads, AppImage launchers and audio service enablement must survive final image assembly.
- NVMe mutation remains forbidden; only `opi-nvme-check` inventory and SMART reads are allowed.

### Physical Orange Pi 5 Pro

- `opi-gpu-check` must identify Mali-G610/PanVK/Panfrost and must not report llvmpipe or lavapipe.
- `opi-stremio-hwcheck`, visible 4K probes and real `opi-stremio-session-check` evidence must prove V4L2 Request decoding from Stremio itself.
- Moonlight must stream at the detected native/preferred display mode with affirmative hardware-decoder evidence.
- `opi-cec-check`, actual TV-remote navigation, HDMI and Bluetooth audio, Wi-Fi/Bluetooth, any-controller input and the EasySMX X20 reference transports must pass.
- The emulator matrix, browser/controller operation, thermal/memory soak and repeated cold boots must pass before final status.

## Explicit non-changes

- Stremio remains native. Lumera would require an Android/Bionic runtime and a second RK3588 graphics/codec integration; it does not reduce the mandatory Linux hardware-decode proof.
- Steam remains visible but experimental and non-blocking.
- The installed NVMe remains read-only during development. After final approval, use the interactive Armbian installer for SD boot plus Btrfs NVMe root; later move boot to eMMC and remove SD only after cold-boot proof.
- No vendor kernel replacement was introduced. The profile continues to use a fresh Armbian edge workspace with explicit audited overrides.

## Evidence reviewed

The latest full logs prove that Armbian fetched and installed its generated `armbian-firmware` package and that previous long builds reached final root customization. They also show that merely seeing `mesa-vulkan-drivers` in APT suggestions is not proof that it was selected or installed. V3.22 therefore treats both firmware and PanVK as explicit, independently checked runtime requirements.
