# V3.25 safe build-speed audit

## Conclusion

V3.25 reduces repeated host build work without relaxing the project's fresh-build or image-acceptance rules. The implementation can reuse verified downloads, dependency-only container layers and compiler/language caches. It cannot reuse a failed workspace, source checkout, application build directory, merged root, Armbian target or generated artifact.

The repository is statically ready for a fresh V3.25 build. The amount of time saved is deliberately unclaimed until two complete timing tables exist: the first run populates caches and a later identical-source run can measure verified hits. A completed image and physical Orange Pi 5 Pro validation remain mandatory.

## Evidence for the change

Four recent Armbian attempts spent 664, 667, 665 and 695 seconds compiling the same Linux 7.1.10 kernel. Their complete Docker phases took 1,339, 1,161, 1,249 and 1,241 seconds. The ten native ARM64 recipes also ran sequentially in separate disposable Ubuntu containers, each repeating package preparation before compilation. Previous logs did not provide reliable elapsed time for every native stage.

This evidence supports caching repeated dependencies/compiler results and adding measurement. It does not support removing gates, reusing failed outputs or increasing concurrency without host resource data.

## Trust boundaries

| Mechanism | Key/verification | Fresh content retained |
|---|---|---|
| ARM64 dependency image | Ubuntu ARM64 image ID + complete build-group hash + schema; architecture, `ccache` and every package rechecked | New container, source checkout, build tree and artifact output |
| Download cache | SHA-256 sidecar on every hit; reviewed expected digest also required where present | Workspace copy, extraction tree and artifact validation |
| Native ccache | `compiler_check=content`, shared 20 GiB limit, per-application namespace | Configure/build/install trees and final executable checks |
| Cargo/Go caches | Isolated per application | Source trees and Cargo target/application output |
| Armbian ccache | Official `USE_CCACHE=yes` Docker path | Fresh Armbian clone, userpatches, rootfs and image |
| Stage timing | Monotonic shell timer; PASS/FAIL row per stage plus total | No build decision is based on timing |

The dependency image contains only declared Ubuntu build packages. Static checks reject references to the artifact or merged-overlay trees in its stage. Native output mounts still point to the new versioned workspace and are deleted after failure.

## Deliberately deferred optimizations

- Native artifacts remain sequential. The current eight-job cap is unchanged because concurrent QEMU builds have not been benchmarked against host CPU, memory and I/O.
- No compiled application or kernel package is promoted into an artifact cache.
- Source Git checkouts remain fresh. Cargo registry and Go module caches reduce downloads but do not replace checkout commit verification.
- Runtime-closure, target-root and completed-image validation remain complete even when every earlier cache hits.
- The output image remains uncompressed, as already required.

## Regression evidence

Repository checks now prove:

- both embedded dependency-image shell payloads parse;
- the dependency image key includes its schema, ARM64 base content and build-package manifest;
- every declared build dependency is verified on a cache hit;
- the dependency image has no artifact/overlay reference;
- native containers require content-verified, namespaced ccache configuration;
- Armbian is invoked with `USE_CCACHE=yes`;
- the persistent cache root is external and unsafe broad/workspace/output paths are rejected;
- a valid cached download is reused;
- a corrupted cached download is rejected and reacquired;
- stage and whole-build timing markers exist;
- all pre-existing package, kernel, controller, display, audio, browser, storage, native Stremio and offline-image invariants remain present.

## Acceptance for the next build

The next complete log must show the dependency image created or verified, cache statistics for every native artifact, explicit Armbian `USE_CCACHE=yes`, a PASS timing row for every stage, terminal offline-image QA and the total timing row. A second unchanged-source build is required before quantifying warm-cache improvement. Cache errors remain build errors; they must never be bypassed by copying data from a cancelled or failed workspace.
