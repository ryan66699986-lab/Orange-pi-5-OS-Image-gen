# V3.19 V3.18-log audit and correction

## Terminal result

The complete V3.18 build log contains 98 lines. Host disk/Docker checks, privileged loop access, fresh-workspace enforcement, ARM64 binfmt execution, all pinned source resolutions, the early Ubuntu Resolute package solver, Stremio's ARM64 ABI/toolchain gate and distro executable/path resolution passed. The next gate stopped with:

```text
==> Official Brave + Firefox ARM64 browser preflight
Official Brave signing-key fingerprint mismatch
```

No native component compilation or Armbian image build started, so no image was produced. V3.18's Moonlight runtime-package correction was therefore not exercised by this run.

## Cause

The repository downloaded Brave's official release APT keyring from the URL in Brave's Linux installation instructions, but compared it with fingerprint `D16166072CACDF2C9429CBF11BF41E37D039F691`. Brave documents that key for verifying the detached signature of `install.sh`; it is not a primary key in the release APT keyring.

At audit time, the official release APT keyring's primary-key set is:

- `DBF1A116C220B8C7164F98230686B78420038257`
- `47D32A74E9A9E013A4B4926C68D513D36A73CD96`
- `B2A3DCA350E67256740DF904DE4EC67BE4B0DCA0`

The downloaded keyring SHA-256 was `c85e85aa3d1783ffaa649ee8dbbc22af7f87192d304602d37e3018226b394788`. The keyring checksum is recorded as audit evidence, not used as the durable gate, because harmless keyring packet/signature maintenance can change the file hash without changing trusted primary keys.

## V3.19 correction

- Extract only primary fingerprints, sort them, and require exact equality with the audited set. This rejects missing or unreviewed new primary keys while allowing certified subkeys.
- Perform the same check in the early ARM64 browser preflight and in the assembled target root.
- Keep APT's signed repository-metadata verification and successful `brave-browser:arm64` installation as mandatory functional checks.
- Assert in the final target root that the Deb822 source still points to Brave's official release URI and binds to the audited keyring path.
- Add static regression assertions for all three fingerprints, both runtime validation layers, the source binding and removal of the wrong installer-script fingerprint.
- Syntax-check embedded `bash -ceu` container programs separately from their outer stage scripts.

V3.19 must use a completely fresh workspace. Static checks and cryptographic repository validation cannot replace the full image build or physical Orange Pi validation.
