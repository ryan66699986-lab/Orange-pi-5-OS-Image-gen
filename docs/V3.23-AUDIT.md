# V3.23 full-log audit

## Scope and result

This audit covers all 48,650 lines of `build(20260826-055314).log`, the complete V3.22 repository package flow, every native artifact recipe, the merged ARM64 closure check, Armbian target customization, final target-root validation and offline-image QA. It also rechecks the unchanged project contract: controller-first native Linux operation, native Stremio with real RK3588 V4L2 Request decoding, broad display/controller/audio compatibility, an experimental non-blocking Steam entry, and no NVMe writes before final image approval.

The run produced no releasable image because the final target-root gate correctly stopped on PPSSPP's unresolved `libGLEW.so.2.2`. V3.23 closes the cause at four independent layers. Repository checks pass, but the generation remains a test candidate until a fresh build completes and the physical Orange Pi validation matrix passes.

## Terminal defect and root cause

PPSSPP compiled and linked in its isolated ARM64 build container because installing `libglew-dev` also installed `libglew2.2`. Its copied `PPSSPPSDL` binary retained a dynamic dependency on `libGLEW.so.2.2`. The generic runtime collector did not provide a sufficiently strong contract: the clean merged-runtime preflight happened to receive GLEW through the dependency solution selected in that empty container, while Armbian's already-populated target root selected a valid package solution without GLEW. The same required package set therefore did not guarantee the same incidental package closure.

The failure was late but valuable: the target-root ELF scan rejected the incomplete root filesystem before a candidate image could be published. The correction is to treat each known mandatory SONAME as an explicit owned dependency rather than assuming it will continue to arrive transitively.

## V3.23 closure matrix

| Layer | New invariant |
|---|---|
| Base package input | `libglew2.2` is a first-class package in `packages/base.txt`, so both early package solving and target installation request it directly |
| PPSSPP artifact | The recipe appends `libglew2.2` to its runtime manifest, verifies the entry after sorting, and requires `PPSSPPSDL` to resolve `libGLEW.so.2.2` immediately after build |
| Merged ARM64 root | The clean pre-Armbian closure requires `libglew2.2` to have installed status and separately requires the PPSSPP SONAME to resolve |
| Armbian target root | The final customization gate requires the package and an explicit PPSSPP-to-GLEW resolved link before the general ELF sweep |
| Completed raw image | Read-only offline inspection requires PPSSPP, the GLEW library path and the `libglew2.2` package record to survive assembly |
| Static regression | Repository validation asserts every declaration and diagnostic so a later edit cannot silently remove one layer |

## Warning review

Two repository-owned warning classes were corrected. Steam's best-effort seed installation now uses `runuser` with an explicit `ryan` environment, avoiding `sudo` hostname resolution inside the Armbian build container. Stremio's desktop entry is normalized to one freedesktop main category (`AudioVideo`) plus the `Video` and `Player` additional categories, preventing duplicate-menu hints.

The remaining `not found` lines in the long log are CMake feature probes for other operating systems, architectures or optional integrations. Git's default-branch messages are informational. Compiler warnings arise in pinned upstream sources and did not change a command result. The Armbian message about absent host `docker buildx` describes cache efficiency, not target correctness; the build continued through kernel/rootfs generation. None is evidence of a second failed stage.

## Unchanged release boundary

A successful V3.23 build and offline QA will create a candidate, not a final image. Real Orange Pi 5 Pro testing must still prove Panthor/PanVK, controller-first ES-DE/Gamescope, Labwc, the EasySMX X20 and other Linux controllers, HDMI and Bluetooth audio, onboard wireless, CEC input, every emulator family, display autodetection, Moonlight hardware decode, and visible Stremio H.264/HEVC/Main10/HDR10/VP9/AV1 V4L2 Request decoding including 4K.

The installed NVMe remains read-only during development. Only inventory and SMART queries are allowed. After the image is accepted, the intended transition is SD boot with a Btrfs NVMe root using Armbian's interactive installer; after eMMC is installed and cold-booted successfully, boot moves to eMMC while the NVMe remains the root filesystem and the SD card can be removed.
