# V3.20 V3.19-log audit and correction

## Terminal result

The complete V3.19 build log contains 48,386 lines. The build passed host, Docker, ARM64 execution, immutable-source, package-resolution, Stremio ABI/toolchain, distro-command, browser, kernel and filesystem preflights. Brave 1.93.138 and Firefox 154.0~build1 installed and executed in the isolated ARM64 preflight, proving V3.19's Brave-key correction.

Snes9x, native Stremio, PPSSPP, ES-DE, gamepad-osk, Moonlight, RMG, Flycast, melonDS and Azahar all completed their ARM64 artifact stages. Azahar reported 64 of 64 tests passing. Armbian then built the kernel and root filesystem and entered target customization. Both Moonlight libraries missing from the V3.16 target, `libsdl2-ttf-2.0-0` and `libqt6quickcontrols2-6`, were unpacked and configured in the real target root.

The final target-root gate stopped with:

```text
gamepad-osk controller mouse is not enabled
```

The build stopped before the remaining target-root assertions, completed-image offline QA, checksum/copy stage and success report. No usable V3.19 image was produced.

## Cause

The pinned `gamepad-osk` commit's example configuration contains an enabled mouse setting with a legal inline comment:

```ini
[mouse]
enabled = true               # enable mouse cursor via right stick
```

V3.19's final validator required only whitespace after `true`, so it rejected the comment. This was a false-negative assertion: the setting was enabled, but the parser did not accept the upstream syntax.

## V3.20 correction

- Normalize the target configuration explicitly. An existing `enabled` key in `[mouse]` becomes exactly `enabled = true`; a missing key or missing section is created.
- Require exactly one `[mouse]` section, preventing a later duplicate section from overriding or confusing the intended value.
- Accept an optional inline comment after `true` in the target-root gate and completed-image offline QA.
- Exercise the exact mutation logic in `tools/check.sh` using disabled-setting, missing-section and inline-comment fixtures.
- Retain the existing Guide+Start OSK chord and all controller, display, media, browser, storage and fresh-workspace policies.

## Warning and probe classification

- GCC diagnostics are emitted by pinned FFmpeg/emulator third-party code; the responsible builds completed and their mandatory gates passed.
- CMake `not found` and failed feature tests are platform or optional-dependency probes (Windows, macOS, Android, x86 SIMD, optional audio/test/documentation backends), not missing declared ARM64 runtime requirements.
- `invoke-rc.d` denials and the fake `start-stop-daemon` warning are expected while packages are installed into an offline image.
- The U-Boot resolver's failed branch-shaped tag probes recover to the valid pinned tag and do not stop Armbian.
- Two container-hostname `sudo` warnings, empty `COLUMNS` notices and Stremio desktop-category hints are non-fatal packaging-environment diagnostics.
- Armbian still does not list Orange Pi 5 Pro edge in `KERNEL_TEST_TARGET`; real board boot, display, media and thermal validation therefore remain mandatory.

V3.20 must start from a completely fresh workspace. A successful build and offline QA still cannot prove real RK3588 V4L2 Request decoding, Panthor/PanVK, controller transports, display modes, audio paths or thermal stability; those remain physical-hardware release gates.
