# V3.27 container-execution and runtime-closure audit

## Outcome

V3.26 is invalid. Its build produced no native artifact, Armbian root filesystem or image. V3.27 replaces the faulty mechanism rather than adding another symptom-specific package.

This record does not claim a numerical probability of build success. It records evidence, failure modes and gates that materially reduce risk. A repository or CI pass cannot prove the complete image or Orange Pi hardware.

## Complete V3.26 log finding

The supplied log contains 527 lines. Host/Docker/loop/binfmt, source resolution, isolated package solvability, Stremio ABI, distro executable, browser, Armbian checkout/kernel metadata, OpenCode and AppImage extraction preflights passed. After about 1,100 stage-seconds, the first native build stopped with:

```text
Cached ARM64 builder lacks command: git
bash: line 1: ccache: command not found
```

The preceding dependency-image stage finished in three seconds and claimed to create a fully populated image. Its installer and verifier used Docker heredocs without `-i`. Docker did not attach stdin, so `bash -seu` received an empty program. The stage committed pristine Ubuntu, and the verifier performed no assertions.

The runtime-closure Docker heredoc used the same invocation. Consequently the closure code introduced in V3.21 and package-owner derivation added in V3.24 had never executed in the logged builds, even though host-side code printed a success line.

## Secondary defects found

Repairing only stdin would still fail. The cached union contained `libcurl4-gnutls-dev` for ES-DE/melonDS and `libcurl4-openssl-dev` for PPSSPP/Flycast. Those development providers conflict. The package preflight succeeded because it correctly solved each recipe group independently; the cache stage incorrectly merged them.

Generic scans also used `ldd ... || true`, so a loader/emulation failure with no literal `not found` text could pass. OpenCode and ARMSX2 mandatory release assets lacked expected digests, and Armbian followed mutable `main`, allowing an unrelated upstream change into the same retry.

## V3.27 design

Stage 18 now pulls Ubuntu 26.04 explicitly for ARM64, validates Docker's architecture and content ID, creates a private tag derived from that ID, runs a bounded architecture receipt and records the identity. It does not install application dependencies.

Every recipe starts from that ARM64 identity, installs common inspection/cache tools, then installs only its declared dependency transaction. Static validation compares each recipe transaction exactly with `packages/build-groups.txt`. Persistent ccache, Cargo and Go caches remain isolated by application; downloads and the official Armbian mirror remain verified and persistent. Outputs remain fresh.

The closure program is a mounted, read-only versioned file. It installs the target runtime set, overlays artifacts, uses `readelf` to identify dynamic ELFs, fails on a nonzero `ldd` result or unresolved library, isolates core/DuckStation/ARMSX2 search paths, maps resolved system libraries to dpkg owners, and writes a sorted package list. A separate receipt records schema, ARM64 architecture, coverage counts, package count, package-list digest and PASS. The host rejects a missing, malformed, undersized or digest-mismatched receipt before Armbian begins. The target root repeats fail-closed dynamic-ELF checks.

Mandatory immutable inputs include:

- Armbian `28699057f79dfd0c4114d8cf0405ccce0a098d0f`;
- OpenCode ARM64 SHA-256 `d30d2cba74617f4e7b96e25563c9572ffe453f9eae70fc0df16286813537ee72`;
- DuckStation ARM64 SHA-256 `e4bedd6285172cc3127fb2634f646d707b5df13e2176579caa39dd9b12ae75a8`;
- ARMSX2 ARM64 SHA-256 `2a4bb7b2aa6ef505e12c071733c160250308b784d4390c7953f8db3046981d0b`.

## Regression matrix

| Failure mode | V3.27 evidence |
|---|---|
| Docker stdin is disconnected | Static check rejects Docker heredocs without `-i`; critical gates are mounted files |
| Mounted gate never runs | External receipt remains empty and is rejected |
| Wrong architecture | Docker metadata, in-container dpkg and receipt must all say ARM64 |
| Common tool missing | Functional ARM64 CI installs and requires every tool |
| Dependency drift/conflict | Exact recipe/group parity plus functional isolated APT simulations |
| `ldd` exits nonzero | Negative fixture must fail; closure and target scans fail closed |
| Library is unresolved | Negative fixture must fail |
| System library has no owner | Merged-`/usr` negative fixture must fail |
| Closure output is empty/stale | Counts, digest, schema and PASS validated outside Docker |
| Required payload changes | Expected SHA-256 enforced before use |
| Armbian changes | Exact commit required in verified mirror and detached checkout |

## Preserved product contract

The repair does not alter controller-first ES-DE, preferred Gamescope, direct ES-DE/Labwc recovery, Labwc-only desktop, native Stremio V4L2 Request proof, Moonlight hardware decode, emulator/browser catalogue, visible experimental Steam, same-release attended updates, UK defaults or the staged SD-root → SD-boot/NVMe-root → eMMC-boot/NVMe-root plan. NVMe remains inventory/SMART-only and non-destructive during image testing.

Required next evidence is a fresh V3.27 build, successful target-root and offline-image QA, then the physical checklist in `VALIDATION.md`. A V3.26 workspace or image must never be resumed or promoted.
