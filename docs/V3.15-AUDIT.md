# V3.15 intensive audit

## Evidence from the V3.14 run

The complete V3.14 log was reviewed through the terminal failure. Host, Docker, loop-device, ARM64 package, source, browser and executable preflights passed. Armbian edge resolved to Linux 7.1. The dedicated Kwiboo V4L2 Request FFmpeg stack compiled, mpv/libmpv installed to the deterministic media prefix, and native Stremio 1.1.4 linked successfully. This proves the V3.13/V3.14 media-build corrections.

The deterministic stop was Snes9x 1.63's bundled glslang commit `9c7fd1a33e5cecbe465e1cd70170167d5e40d398`. `SPIRV/SpvBuilder.h` declares `uint32_t` without directly including `<cstdint>`, which GCC 15 no longer supplies transitively. V3.15 applies that one-line compatibility correction only after checking the expected pinned layout and then syntax-compiles the header before the complete 226-target build.

## Media decision

Stremio remains the supported media application. It is already a native ARM64 GTK/Wayland program in this image and V3.14 proved its full compilation against the audited media prefix. Lumera targets Android TV and Media3/ExoPlayer; adopting it would require an Android container plus compatible RK3588 Android graphics and codec-HAL integration. That would introduce a second platform and would not validate Linux V4L2 Request decoding. The risk and memory cost are inappropriate for the 4 GB target.

Hardware decoding is non-negotiable. The image therefore rejects software-only success and provides two layers of evidence: isolated codec probes through the same FFmpeg/mpv stack and application-process logs from real Stremio and Moonlight sessions.

## V3.15 corrections and strengthened gates

- Snes9x and its nested glslang source are pinned and fail fast on source drift or header incompatibility.
- Moonlight v6.1.0 is pinned to commit `f786e94c7b2f943e24e65d7d74deb539b827fc84` at source-resolution time.
- Moonlight builds only after the successful Stremio media artifact is mounted read-only; pkg-config prefixes, ELF RUNPATH and runtime `libavcodec`, `libavutil` and `libswscale` resolution must all point to `/opt/opi/media`. Moonlight intentionally does not link `libavformat`, so the gate follows its actual pinned link graph rather than demanding an unused library.
- Moonlight defaults to 3840×2160 at 60 Hz, automatic codec selection, HDR enabled and forced hardware decoding. Real-session validation requires a 3840×2160 stream plus the patched positive hardware-decoder record.
- Stremio probes include H.264, HEVC 8-bit, HEVC Main10, H.264 4K, HEVC Main10 4K HDR10/PQ, VP9 4K and AV1 4K. Every probe is generated and inspected before Armbian starts.
- Kernel overrides explicitly retain Rockchip DRM/HDMI-QP, HDMI-CEC, Panthor, VDEC, HDMI audio, onboard Wi-Fi/Bluetooth and common gamepad/force-feedback drivers.
- All 56 kernel overrides were checked for existence and compatible boolean/tristate types against the exact upstream Linux 7.1 Kconfig. The nonexistent legacy-style `SND_SOC_ROCKCHIP` parent was excluded; the real `SND_SOC_ROCKCHIP_I2S_TDM` driver and its ALSA/HDMI dependencies remain mandatory.
- PipeWire HDMI/DisplayPort and Bluetooth audio, the EasySMX X20 reference controller, Wi-Fi/Bluetooth, controller input permissions, service enablement and the controller-first session all have target or runtime gates.
- The finished image is mounted read-only and checked for critical files, AArch64 ELFs, kernel configuration, services, sleep masks, media policy, Moonlight RUNPATH, browser/session configuration and forbidden legacy packages before it is copied to the output directory.
- All network Git operations are non-interactive and bounded by time and low-speed limits. An unreachable upstream now fails with a useful diagnostic instead of leaving the builder hung indefinitely.
- Every native Git build is resolved to an immutable commit before compilation and compared with the produced artifact's recorded commit. Tags remain human-readable labels only.

## Storage policy

The installed NVMe is intentionally excluded from build and installation activity. `opi-nvme-check` performs only `lsblk` inventory and `nvme smart-log` reads. Static checks reject partitioning and formatting commands in the profile.

After the image is declared final on SD, Armbian's interactive `/usr/bin/armbian-install` is the intended tool to keep boot on SD while moving the root filesystem to NVMe. That operation must be performed only after confirming exact device identities and making a backup. When eMMC is later installed, boot can migrate there and the SD card can be removed.

## What remains hardware-dependent

Repository analysis cannot prove the behavior of a physical Orange Pi, display, receiver, Bluetooth radio or NVMe. V3.15 must still complete a fresh host build and the final image must pass `opi-validate`, visible Stremio probes, real Stremio playback, a real Moonlight 4K stream, EasySMX transport tests, both audio paths and thermal/memory soak testing. These are release gates, not deferred implementation work.
